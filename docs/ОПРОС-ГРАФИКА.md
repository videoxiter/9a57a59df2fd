# План: опрос пожеланий и график работы внутри сервиса

Собрано по фактам: разобраны 16 страниц графиков Confluence (2024-09 … 2026-11),
легенда символов, последний месяц (pageId 452755676), опрос WebAsk
(«График работы на Ноябрь 2026г.»), выгрузка Jira HELP-394909
(`График на месяц/HELP-394909.xml`) и страница отпусков (pageId 430081574).
Правила линий, дежурств, сроков и публикации — со слов руководителя.

## 1. Факты

**Смены:** 1 — 05:00–13:00, 2 — 09:00–18:00, 3 — 10:00–19:00.
**Выходные смены:** I — 05:00–14:00, II — 08:00–17:00, III — дневная доп.,
2Р/3Р — рабочий выходной сменой 2/3.
**Дежурства:** Ср — «срочка» (09:00–18:00), Т — «Тания» (09:00–18:00).
**Прочее:** В выходной, О отпуск, Б больничный, У учебный, Я отработка,
НВ отгул с отработкой, X отгул за свой счёт, К командировка, С семинар, Д доп. смена.

**Линии и нормы (из правил руководителя):**

| Линия | Норма | Кто может стоять |
| --- | --- | --- |
| L0 | всегда 1 | Фролов или Болгов (главный / ведущие) |
| L1.1 | минимум 3 | Юрьев, Агарков, Вторыгин, Завьялов, Хасанов |
| L1.2 | минимум 1, лучше 2 (будни 10:00–19:00) | по будням смена 3; может быть из L2.2 или другой, если людей хватает |
| L2.1 | 2 | Мельников, Пестовский, Елисеев, Юрьев |
| L2.2 | 1 | обычно Пестовский, иначе Юрьев |
| L2.3 | 1 | обычно Мельников, иначе Елисеев |
| L2.4 | 1 | обычно Поспелова, иначе Мельников |
| ночной | 1 | обычно Завьялов, иначе по назначению |

**Правила:** предел 6 смен подряд; выходные — как получится.
**Дежурные:** «Тания» — по очереди Болгов → Мельников → Елисеев (нижний приоритет);
«срочка» = L0, по очереди Фролов и Болгов.
**Особые дни:** 01–02 января и 08 марта — смен нет; 31 декабря и 07 января и
отдельные праздничные могут быть укорочены — правит руководитель в моменте.
Остальные нерабочие дни — по производственному календарю РФ; его нужно
показывать сотруднику при заполнении пожеланий.
**Опрос WebAsk (5 вопросов):** ФИО; желаемые выходные смены (даты + время 05/08,
«больше», «без выходных», «неважно», «другое»); обязательные выходные (даты +
причина); недели для 3-й смены / «без 3-й» / «Я Ночной Хулиган»; готовность
дежурить по «Тании» (да/нет).
**Формат тикета (HELP-394909):** задача на месяц, статус «Закрыта»; в комментариях
таблицы «ФИО | Желаемые даты | Предпочтения» по каждому вопросу, выводы
(например, «Фролов — единственный, кто указал недели для 3-й смены»), в конце —
ссылка на страницу графика.
**Отпуска:** страница «График отпусков на 2026г.» (430081574), таблица
«ФИО | Период | Дней | ВрИО»; периоды вида «12 января - 16 января».
**Дни рождения:** Яковлев 14.03.1988, Фролов 11.07.1999, Болгов 02.07.2002,
Мельников 05.04.1995, Хасанов 03.11.1999, Пестовский 26.05.1997,
Елисеев 29.09.2003, Завьялов 21.08.1996, Юрьев 22.02.1994,
Агарков 28.09.2004, Вторыгин 02.02.2003, Поспелова 27.01.2000.

## 2. Цикл месяца

опрос → ответы → авто-график → ручная правка → «Утвердить» → публикация
(сайт + Confluence-страница + xlsx) → уведомления.

### 2.1 Опрос

- Руководитель создаёт опрос на месяц, задаёт срок сдачи (сам решает),
  отмечает особые дни (праздник без смен, укороченный) и подтверждает правила линий.
- Сотрудник видит календарь месяца с подсветкой праздников и своего отпуска,
  отвечает на те же 5 вопросов, что в WebAsk; правки до срока.
- Сотруднику доступен производственный календарь РФ прямо в форме (подсказка
  «праздник / рабочая суббота»).
- Руководителю — сводка ответов как в тикете (таблицы по вопросам),
  «кто не ответил», напоминание, экспорт CSV.
- ФИО не вводится руками — берётся из аккаунта (ошибка «ФИО: !!!» в старой
  форме исключается).

### 2.2 Автосборка

Порядок: жёсткие ограничения → нормы линий → пожелания → равномерность → ротация.

1. Отпуска (из страницы отпусков и заявок), праздники без смен — дни исключены.
2. Линии: на каждый день проверяем минимумы (L0 1, L1.1 ≥3, L2.1 2, L2.2 1,
   L2.3 1, L2.4 1, ночной 1; L1.2 — по будням).
3. Пожелания: выходные смены только в сб/вс/праздники; обязательные выходные —
   не ставим смену; 3-я смена — только тем, кто указал недели; «без выходных
   смен» — не ставим выходные.
4. Предел 6 смен подряд, затем обязательный выходной.
5. Дежурства: «Тания» по очереди Болгов → Мельников → Елисеев, «срочка» — L0
   по очереди; учитывается отпуск и «нет» из ответа.
6. Равномерность: при равенстве кандидатов смену получает тот, у кого меньше
   смен в месяце и кто дольше без смены.
7. Результат — черновик + **отчёт**: какие пожелания не выполнены и почему
   (нет людей на линии, отпуск, лимит подряд, «нельзя двоим одновременно» и т. п.).

### 2.3 Ручной режим

Таблица «люди × дни» с неделями, итоги по человеку (смены, часы, выходные,
выходные смены). Ввод символа: одна ячейка, выделение мышью, Shift+клик,
«вся неделя», «будни/выходные», «шаблон по кругу», «копировать неделю»,
«поменять у двоих», отмена/повтор. Подсветка нарушений (нормы линий, 6 подряд,
пожелание нарушено, отпуск, нет 3-й смены у сотрудника). Переключение
«Авто ↔ Ручной» не теряет правок; кнопка «Пересобрать» с подтверждением.

### 2.4 Утверждение и публикация

- Кнопка **«Утвердить»**: фиксирует месяц, создаёт страницу в Confluence
  под родительской «Графики рабочего времени» (57901080) по образцу текущих,
  формирует **xlsx с окраской**, публикует данные на сайт (страницы сотрудников
  сразу показывают новый график).
- До утверждения — черновик (виден только руководителю).
- После утверждения правки только руководителем, каждая — с записью
  «кто, когда, что, причина», и уведомлением сотруднику.
- Версия и откат; история хранится в базе.

### 2.5 Уведомления

- Новый опрос → «ДисКо» + приложение всем, кому положено.
- Напоминание за день до срока — не ответившим.
- «График на декабрь утверждён» → всем; личные изменения → адресно.
- Изменения заявок (отгул, увольнительная, переработка) → сотруднику
  в приложении и в «ДисКо».

## 3. Данные (Supabase)

```
otp_polls          id, month, status(draft|open|closed|approved), due_at,
                   params jsonb (праздники, укороченные дни, нормы линий),
                   created_by, approved_at, version
otp_poll_answers   id, poll_id, emp_slug, code, value jsonb, updated_at
otp_schedule       month, cell jsonb (emp → day → символ), status(draft|published),
                   updated_at, updated_by, version
otp_schedule_log   id, month, at, by, action, payload jsonb
otp_lines          month, line, day, emp_slug  (распределение по линиям)
```

Сайт читает `otp_schedule` (published) → `data.js` → страницы; Confluence и xlsx —
артефакты публикации.

## 4. Этапы

| Этап | Что делаем | Приёмка |
| --- | --- | --- |
| 1. Опрос | Таблицы, создание опроса, 5 вопросов, ответы, сводка, напоминания | Опрос на декабрь создан; сотрудник отвечает за 2 минуты; видно, кто не ответил |
| 2. Таблица графика | Сетка месяц × люди, ввод и массовые операции, подсветка, черновик | Месяц расставляется с нуля за 10 минут; символы совпадают с Confluence |
| 3. Автосборка | Нормы линий, правила, генератор, отчёт о невыполнимых пожеланиях | Авто-месяц проходит проверки норм и 6 подряд; отчёт объясняет отказы |
| 4. Утверждение | Кнопка «Утвердить», страница Confluence, xlsx с окраской, публикация на сайт, откат | После утверждения сайт показывает новый график; откат возвращает прошлый |
| 5. Уведомления | «ДисКо» + приложение: опрос, напоминание, утверждение, изменения | Сотрудник получает уведомление об опросе и об утверждении; правка — адресно |

Порядок 1 → 2 → 3 → 4 → 5. Декабрь 2026: если сроки позволяют — этапы 1–4,
иначе декабрь собирается в таблице (этап 2), а опрос запускается с января.
