# План: опрос пожеланий и график работы внутри сервиса

Документ собран по фактам: разобраны все страницы графиков Confluence (16 страниц,
2024-09 … 2026-11), легенда символов и последний актуальный месяц
(pageId 452755676, ноябрь 2026), а также пройден пример опроса WebAsk
(«График работы на Ноябрь 2026г.»). Jira-тикет HELP-394909 без авторизации
недоступен (редирект на SSO) — его формат нужно прислать текстом.

## 1. Что сейчас есть (факты)

**Смены и символы** (легенда `scripts/schedule.json`, 20 значений):

| Символ | Смысл | Время |
| --- | --- | --- |
| 1 / 2 / 3 | смены 1 / 2 / 3 | 05–13 / 09–18 / 10–19 |
| I / II / III | выходные смены 1 / 2 / дневная дополнительная | 05–14 / 08–17 / — |
| 2Р / 3Р | рабочий выходной (смена 2 / 3) | 09–18 / 10–19 |
| Ср / Т | дежурный по «срочке» / дежурство «Тания» | 09–18 |
| Д | дополнительная смена | — |
| В | выходной | — |
| О / Б / У | отпуск / больничный / учебный отпуск | — |
| Я / НВ / X | отработка за отгул / отгул с отработкой / отгул за свой счёт | — |
| К / С | командировка / семинар | — |

**Структура месяца:** сетка «ФИО × дни» (12 человек в ноябре 2026), плюс
распределение по линиям по неделям (`L0` — супервайзинг и контроль, далее
`L1.x` и т. д.). Сейчас на странице месяца 8 линий.

**Особые дни (по указанию руководителя):**
01–02 января и 08 марта — смен нет совсем; 31 декабря, 07 января и отдельные
праздничные дни могут быть **укороченными** (решение задаёт руководитель).

**Опрос (WebAsk) — 5 вопросов:**
1. ФИО (текст, обязательный).
2. Даты желаемых **выходных смен** (мультивыбор дат; варианты «больше»,
   «без выходных смен», «неважно», «другое» — время 05:00 или 08:00).
3. Даты, которые **нужны выходными обязательно** (мультивыбор; «оставить
   выходными», «меньше выходных», «неважно», «другое» + причина).
4. Недели для **3-й смены** (10:00–19:00, L1.2) или «без 3-й смены»;
   для сотрудников 1-й смены — «Я Ночной Хулиган» (только Максим/замещающий).
5. Готовность быть **дежурным по МКК «Тания»** (да/нет).

## 2. Что делаем

Единый цикл в сервисе: **опрос → ответы → авто/ручной график → публикация на сайт
→ уведомления**, без Confluence как источника данных (Confluence — только выгрузка).

### 2.1 Опрос

- Руководитель создаёт опрос на месяц (декабрь 2026), задаёт: срок сдачи,
  список дней месяца с пометками (рабочий / выходной / праздник / укороченный),
  набор вопросов.
- Вопросы по умолчанию — те же 5, что в WebAsk, но с учётом наших данных:
  вместо свободного «ФИО» сотрудник выбирается из списка (или вход по ссылке),
  даты показываются календарём месяца.
- Сотрудник заполняет на сайте (раздел «График» → «Пожелания») и/или в приложении
  (уведомление «Открыт опрос на декабрь»), правит до срока.
- Руководителю — сводная таблица ответов: кто ответил, кто нет; пожелания
  по датам; экспорт CSV; «напомнить не ответившим».

### 2.2 Автосборка

Правила (задаются в настройках опроса, меняются без кода):

- норма людей на линии по дням недели (будни / выходные / праздники);
- смены: 1/2/3 по пожеланиям и ротации; ограничение смен подряд (например, 5);
- выходные смены: только по субботам/воскресеньям и праздникам, из пожеланий;
- дежурный «Тания» и «срочка» — по кругу среди согласных;
- учёт отпусков, отгулов, увольнительных, больничных (уже есть в заявках);
- праздники: 01–02.01, 08.03 — смен нет; укороченные дни — по флагу.

Алгоритм: сначала жёсткие ограничения (отпуска, «не могу», праздники),
затем пожелания по приоритету, затем равномерность (кто меньше работал —
получает смену), затем ротация смен по кругу. Результат — черновик графика
с **отчётом о невыполнимых пожеланиях** (кто и почему не получил).

### 2.3 Ручной режим

Таблица как в Confluence: строки — сотрудники, столбцы — дни месяца
(с разделением по неделям), внизу — итоги по человеку (смены, часы).

- **Массовые операции:** выделить диапазон (мышью или Shift+клик) → поставить
  символ; «вся неделя»; «будни выбранной сменой»; «по шаблону» (например,
  2 2 В В 2 2 В по кругу); «скопировать неделю»; «выровнять по образцу».
- **По одной ячейке** — тоже работает.
- Подсветка конфликтов: недобор/перебор людей на линии, смены подряд,
  пожелание «просил выходной — поставлена смена», отпуск.
- Отмена/повтор (10 шагов), история: кто и когда менял ячейку.
- Режимы: **«Авто»** (кнопка «Пересобрать»), **«Ручной»** (правки), переключение
  не теряет правок; можно взять авто-результат и поправить.

### 2.4 Публикация

- Кнопка **«Опубликовать»**: сохраняет месяц в `data.js` (раздел `schedule`),
  пересобирает страницы сотрудников, публикует на сайт.
- После публикации страницы берут график **из нашего файла**, не из Confluence;
  часы, перерывы и обеды — из легенды символов.
- Состояния: черновик → опубликован; версия и дата публикации; **откат**
  к предыдущей версии; правки после публикации — только руководитель,
  каждая с записью «изменено Яковлевым Е.Е., дата, причина».
- Выгрузка в Confluence: отдельная кнопка «Выгрузить в Confluence» —
  обновляет/создаёт страницу месяца с той же таблицей (по шаблону текущих страниц).

### 2.5 Уведомления

- **Новый опрос** → «ДисКо» + уведомление в приложении всем, кому положено.
- **Напоминание** за 1 день до срока — тем, кто не ответил.
- **График опубликован** → всем сотрудникам: «График на декабрь готов».
- **Изменения после публикации** (смена, выходной, отгул, увольнительная,
  переработка) → личное уведомление сотруднику в приложении и в «ДисКо».
  Приложение уже умеет сравнивать данные страницы и сообщать «Новое на странице».

## 3. Данные (Supabase)

```
otp_polls        id, month 'YYYY-MM', status (draft|open|closed|published),
                 due_at, params jsonb (правила, нормы, праздники, укороченные дни),
                 created_by, published_at, version
otp_poll_questions  id, poll_id, code, title, kind, options jsonb, required, ord
otp_wishes       id, poll_id, emp_slug, question_code, value jsonb, updated_at
otp_schedule     month, cell jsonb  (emp_slug → day → symbol),
                 status (draft|published), updated_at, updated_by, note
otp_schedule_log id, month, at, by, action, payload jsonb
```

Публичные страницы читают только `otp_schedule` со статусом `published`
(страницы генерируются из `data.js` как сейчас, источник — наш файл).

## 4. Этапы

| Этап | Что делаем | Приёмка |
| --- | --- | --- |
| **1. Опрос** | Таблицы, создание опроса, 5 вопросов, ответы с сайта, сводка для руководителя, напоминания | Руководитель создаёт опрос на декабрь; сотрудник отвечает за 2 минуты; видно, кто не ответил; повторный ответ не дублируется |
| **2. Таблица графика** | Сетка месяц × люди, ввод символов, массовые операции, подсветка конфликтов, черновик | Можно расставить месяц с нуля за 10 минут; кириллические символы совпадают с Confluence |
| **3. Автосборка** | Правила, генератор по пожеланиям, отчёт о невозможных пожеланиях | Авто-месяц проходит проверки: норма на линии, смены подряд, праздники; отчёт объясняет каждый отказ |
| **4. Публикация** | Кнопка «Опубликовать», запись в `data.js`, пересборка страниц, версии и откат | После нажатия страницы сотрудников показывают новый график; откат возвращает предыдущий |
| **5. Уведомления и обмен** | «ДисКо» + приложение: опрос, напоминание, публикация, изменения; выгрузка в Confluence | Сотрудник получает уведомление об опросе и о публикации; правка после публикации даёт личное уведомление |

Порядок: 1 → 2 → 3 → 4 → 5. Этап 1 можно запустить уже на декабрь, если
до сдачи пожеланий остаётся время; иначе — январь, а декабрь добрать вручную
в таблице (этап 2).

## 5. Что нужно от тебя (по пунктам)

1. **Правила нормы:** сколько человек нужно на линии в будни, в выходные,
   в праздники (по каждой линии).
2. **Предел смен подряд** и правило «сколько выходных минимум в неделю».
3. **Дежурные:** как чередуются «Тания» и «срочка», сколько дней подряд.
4. **Укороченные дни:** какие даты декабря 2026 укорочены и на сколько часов.
5. **Срок сдачи пожеланий** в декабре (за сколько дней до 1 декабря).
6. **Выгрузка в Confluence:** обновлять существующую страницу месяца или
   создавать новую (и под какой родительской страницей).
7. **Jira HELP-394909:** пришли текст/скриншот тикета — формат учту
   (например, как выглядит ответ «итоговый график» и комментарии).
8. **Утверждение:** нужен ли шаг «согласовано» перед публикацией.
