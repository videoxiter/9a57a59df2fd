Техническая документация: архитектура, данные, API и эксплуатация

Статический сайт + Supabase. Версия документа: 13.11.2026

1. Назначение

Внутренний портал отдела технической поддержки: дашборд эффективности (KPI, рейтинг, динамика), персональные страницы сотрудников (бонусы, LVL, награды, рост, статистика, доход), учёт рабочего времени («Стартовая»), отчёты для руководителя, уведомления в Яндекс Мессенджер.

СлойТехнологияГде размещён
ФронтендСтатический HTML + vanilla JS/CSSGitHub Pages (репозиторий videoxiter/9a57a59df2fd, ветка main)
ДанныеSupabase (Postgres + PostgREST + Edge Functions)проект Supabase
ГенерацияPython 3 (стандартная библиотека)локально/CI, результат коммитится

2. Архитектура

Confluence (выгрузка) ─┐
itogi/*.txt            ├─→ scripts/*.py ─→ HTML-страницы + assets/data/*.json ─→ git push ─→ GitHub Pages
extracted.json         │
schedule.json          ┘                                   │
                                                          ├─→ Supabase (события времени, заявки, сотрудники, контент)
                                                          └─→ Edge Functions (notify, cron) ─→ Яндекс Мессенджер

Сайт не имеет собственного бэкенда: браузер обращается к Supabase REST/RPC и к Edge Functions напрямую по публичному ключу. Учётные записи и защита страниц — сессии в otp_sessions.

7. REST API — примеры

Базовый адрес: https://<project>.supabase.co/rest/v1. Заголовки: apikey: <ключ>, Authorization: Bearer <ключ>.

# события за день
GET /otp_time_events?select=*&day=eq.2026-11-12&order=at.asc

# сводка по дням
GET /otp_time_days?select=*&day=eq.2026-11-12

# текущий статус (RPC)
POST /rpc/otp_current_status  {}

# заявки (увольнительные/корректировки)
GET /otp_requests?select=*&status=eq.approved&order=date.desc

# вход
POST /rpc/otp_login  {"p_slug":"admin","p_pass":"..."}

# контент сотрудника
POST /rpc/otp_content_list  {"p_emp":"bolgov"}

9. Учётные записи и защита

  • Пароли хранятся как bcrypt-хеш (crypt(pass, gen_salt('bf'))), проверка — только в RPC.
  • Сессия: токен uuid в otp_sessions на 60 дней, в браузере — localStorage["otp_sess_<slug>"].
  • Дашборд закрыт паролем администратора (auth.js → OTP_AUTH.protect("admin", true)); личные страницы — если сотруднику задан пароль.
  • Ограничение: страницы статические, данные приходят в HTML — защита визуальная. Для реальной защиты нужен прокси (см. раздел 12).

10. Учёт рабочего времени

  • Норма дня — 7 ч 30 мин (9-часовая смена минус обед и два тех.перерыва по 15 минут).
  • Отработано = сумма интервалов «работа → пауза»; незакрытый интервал сегодняшнего дня считается до текущего момента.
  • «Временное отсутствие: Без заявки» — статус фиксируется, но рабочее время не останавливает.
  • Увольнительная (leave) — пауза только внутри интервала from–to; кнопка «Завершить увольнительную» сокращает интервал до текущего времени.
  • Язык время: МСК (UTC+3), независимо от пояса браузера.

12. Известные ограничения и план

  • Данные в HTML. Для реальной защиты нужен прокси: Edge Function api, которая держит service-role ключ, проверяет сессию и отдаёт данные; клиент ходит только в неё. Публичный ключ из data.js при этом убирается.
  • Часы в заявках: увольнительная «не списывать» помечается маркером в тексте заявки ([[OTP-META:{"noDeduct":true}]]) — хрупко, лучше отдельное поле no_deduct.
  • ФИО в otp_time_events приходит из профиля; в Confluence бывают написания на одну букву иначе (Радион/Родион) — сопоставление по внутреннему id.
  • Пароли личных страниц включаются только после того, как руководитель задал пароль в админке.
