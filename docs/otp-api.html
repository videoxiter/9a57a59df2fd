JSON API

Интеграция «Моей команды ОТП» с внешними системами

Базовый адрес: https://<project>.supabase.co · Версия: 13.11.2026

1. Способы доступа

СпособАдресАутентификация
Прокси (рекомендуется)POST /functions/v1/apiтокен сессии (uuid) внутри JSON
Прямой REST/rest/v1/...apikey + Authorization: Bearer <ключ>

Прокси держит service-role ключ на сервере; публичный ключ наружу не отдаётся. Прямой REST доступен, пока публичный ключ не отключён.

2. Прокси: формат запроса

{
  "token":  "8f3c...uuid сессии",
  "path":   "otp_time_events?select=*&day=eq.2026-11-12",
  "method": "GET",          // GET | POST | PATCH
  "body":   [ { ... } ]     // только для POST/PATCH
}

Ответ — тело PostgREST как есть (JSON-массив объектов) и тот же HTTP-код.

КодЧто значит
200успех
401unauthorized — токена нет или он просрочен
403table not allowed / method not allowed / inactive
5xxошибка Supabase (проброс статуса)

Разрешённые таблицы прокси: otp_time_events (GET/POST/PATCH), otp_requests (GET/PATCH), otp_content (GET), otp_staff (GET).

3. Каталог операций

3.1. События времени за день

path: "otp_time_events?select=*&day=eq.2026-11-12&order=at.asc"
[{
  "id": "ev-1794057858723-x1y2",
  "empSlug": "e5d35a6fc921",
  "empName": "Болгов Андрей Владимирович",

  "type": "break_start",

3.7. Записать событие (POST)

path: "otp_time_events"
method: "POST"
body: [{
  "id": "ev-1794057999000-abcd",
  "empSlug": "e5d35a6fc921",
  "empName": "Болгов Андрей Владимирович",
  "day": "2026-11-12",
  "type": "shift_start",
  "slot": null,
  "at": "2026-11-12T09:00:00+03:00",
  "reason": null
}]

id должен быть уникальным (любая строка, например ev-<epoch>-<random4>).

3.8. Снимок дня: статус + история событий с временем

POST /rest/v1/rpc/otp_day_snapshot   body: {"p_slug":"bolgov","p_day":"2026-11-12"}
{
  "empSlug": "bolgov",
  "day": "2026-11-12",
  "status": "work",
  "since": "2026-11-12T11:45:46+00:00",
  "reason": null,
  "events": [
    { "type": "shift_start", "slot": null, "reason": null, "at": "2026-11-12T11:23:16+00:00" },
    { "type": "break_start", "slot": "tech1", "reason": null, "at": "2026-11-12T11:23:23+00:00" },
    { "type": "break_end", "slot": "tech1", "reason": null, "at": "2026-11-12T11:23:32+00:00" }
  ]
}

Каждое событие содержит at — точное время, когда статус был получен. Текущий статус — последнее событие.

3.9. Линия и график на день

График хранится в статическом JSON (GitHub Pages), а не в Supabase:

GET https://videoxiter.github.io/9a57a59df2fd/assets/data/schedule.json
{
  "team": [{ "fio": "Болгов Андрей Владимирович", "id": "bolgov" }],
  "schedule": {
    "months": {
      "2026-11": {
        "shifts": {
          "Болгов Андрей Владимирович": {
            "12": { "sym": "2", "title": "Смена 2", "kind": "shift", "time": "09:00–18:00" }
          }
        },
        "lines": {
          "L3": { "title": "L3 · тех.инженеры",
                  "weeks": [["Болгов Андрей Владимирович"]],
                  "labels": ["01.11-15.11"] }
        }
      }
    }
  }
}

Линия определяется по фамилии сотрудника в lines[<id>].weeks с учётом labels (период недели). График — shifts[ФИО]["<день>"].

4. Примеры

4.1. Через прокси (curl)

curl -X POST "https://<project>.supabase.co/functions/v1/api" \\
  -H "Content-Type: application/json" \\
  -d '{"token":"<uuid>","method":"GET","path":"otp_time_events?select=*&day=eq.2026-11-12"}'

4.2. Прямой REST (curl)

curl "https://<project>.supabase.co/rest/v1/otp_time_events?select=*&day=eq.2026-11-12" \\
  -H "apikey: <ключ>" -H "Authorization: Bearer <ключ>"

4.3. Python

import requests
r = requests.post(
    "https://<project>.supabase.co/functions/v1/api",
    json={"token": TOKEN, "method": "GET",
          "path": "otp_time_days?select=*&day=eq.2026-11-12"},
    timeout=20,
)
for row in r.json():
    print(row["empName"], row["worked_sec"])

4.4. JavaScript

const res = await fetch(`${SUPABASE}/functions/v1/api`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ token, method: "GET", path: "otp_current_status" }),
});

5. Аутентификация токеном

Токен сессии выдаёт otp_login:

POST /rest/v1/rpc/otp_login   body: {"p_slug":"admin","p_pass":"<пароль>"}
→ {"ok":true,"token":"<uuid>","slug":"admin","admin":true}

Срок жизни — 60 дней. Проверка: POST /rest/v1/rpc/otp_check_session с {"p_token":"<uuid>"}.

7. Ограничения и правила

  • Часовой пояс расчётов — Europe/Moscow (UTC+3).
  • Норма дня — 7 ч 30 мин.
  • Прокси не разграничивает данные между сотрудниками — любой вошедший видит все разрешённые таблицы.
  • Прямой REST работает, пока публичный ключ не отключён; после включения прокси его следует убрать.
  • Идемпотентность событий — по id: повтор с тем же id вернёт ошибку уникальности.
