## P2. UX / missclick / визуал

### P2.1. Защита от missclick: «10 секунд до применения» (ВЫБРАННЫЙ ВАРИАНТ) — ВЫПОЛНЕНО

**Принцип.** Опасное действие не выполняется по клику — оно входит в «pending»-состояние на
**10 секунд**: кнопка показывает «Завершится через N с», рядом появляется «Отмена».
Таймер истёк — действие применяется (те же самые push + stAdd + уведомление).
Журнал append-only не трогаем — мы только замедляем запись.

**Под защитой** (profile.js → `initStart`, click handler L2391-2480):

| act | Кнопка | Текст таймера |
|---|---|---|
| `stop` | Завершить смену | «Смена завершится через 10 с» |
| `slot-tech1` / `slot-tech2` / `slot-lunch` (is-run) | Завершить перерыв / обед | «Перерыв завершится через 10 с» |
| `absence` (active) | Завершить отсутствие | «Отсутствие завершится через 10 с» |
| `leave-end` | Завершить увольнительную | «Увольнительная завершится через 10 с» |

**НЕ под защитой** (быстрые, низкий риск): «Начало смены», открытие перерыва, открытие
отсутствия (у него и так форма с причиной). Анти-двойной-клик 3 с (L2418-2420) сохраняется
для всех действий.

**UI (4 элемента, всё в существующем секционном HTML `#st-actions`):**
1. Кнопка действия получает класс `is-pending`: красная рамка + CSS-пульс, текст меняется
   на «…через 9 с» (секунды обновляет существующий `tickLive` с периодом 1 с —
   profile.js L2283, L2527; отдельный таймер не нужен, перерисовка только span, как сейчас).
2. В строке кнопок — отдельная «Отмена» (btn-ghost, ph-x).
3. Статусная строка `#st-status` на время окна: «⏳ Смена завершится через 9 с».
4. Тонкий прогресс-бар под кнопкой: CSS `transition: width 10s linear` (100% → 0),
   задаётся один раз при старте — плавность без JS на каждом кадре.

**Поведение и граничные случаи:**
- Во время окна **все остальные кнопки disabled** (кроме «Отмена») — исключает «а пока я
  заодно ещё что-то нажал» и конфликты состояний.
- **Отмена** → `pending = null`, `render()`. В журнал ничего не попало, уведомление не шло.
- **Истечение** → вызов того же `execute(act)`, что и при обычном клике. Уведомление в
  «ДисКо» уходит ровно в момент применения — канал не спамится во время отсчёта.
- **Гарды состояния сохраняются**: если за 10 с смену закрыли с другого устройства,
  `execute()` упрётся в `if (!st.started || st.stopped) return;` — безопасный no-op,
  двойного `shift_stop` не будет (см. L2406-2411).
- **Обновление/закрытие вкладки в окне отсчёта = действие сброшено** (консервативно:
  подтверждение не завершено — события нет). Задокументировать в README.
- `stSync` (15 с, L2494-2500) делает `render()`, но pending — замыкание, перерисовка его
  не сбрасывает; после stSync-обновления данных execute() работает по свежим событиям.
- **Старая молчаливая защита** «закрытие перерыва < 10 с после открытия игнорируется»
  (L2424-2425) **заменяется видимым отсчётом**: нажал закрыть сразу после открытия —
  видишь отсчёт и «Отмена», а не «почему не сработало».
- `stNotify` (L2017) сейчас — no-op, уведомления реально шлются из `stAdd` (L2053) —
  менять ничего не нужно, просто не забыть.

**Реализация (каркас, ~60 строк в profile.js):**
```
const ST_CONFIRM_MS = 10000;
const CONFIRMABLE = new Set(["stop", "absence", "leave-end"]);   // + "slot-*" в is-run
let pending = null;   // { act, slot?, until }

/* клик: вместо прямых if-цепочек */
const click = (act, st) => {
  if (act === "cancel-pending") { pending = null; render(); return; }
  if (isConfirmable(act, st)) { pending = { act, until: Date.now() + ST_CONFIRM_MS }; render(); return; }
  execute(act, st);   // execute() = текущая if-цепочка L2400-2479 без изменений
};

/* в tickLive (L2283): */
if (pending) {
  const left = Math.ceil((pending.until - Date.now()) / 1000);
  const span = box.querySelector('.st-btn.is-pending span');
  if (span) span.textContent = pendingLabel(pending) + ` · ${Math.max(0, left)} с`;
  if (Date.now() >= pending.until) { const p = pending; pending = null; execute(p.act); }
}

/* в render(): если pending — все кнопки disabled, кроме cancel; pending-кнопка
   получает is-pending и прогресс-бар */
```
CSS: `.st-btn.is-pending { border-color: var(--danger); animation: st-pulse 1s infinite; }`
+ `.st-pend-bar` (width 100% → 0, 10s linear). Дубль для дашборда — не требуется:
кнопки управления временем есть только на profile-страницах (`renderNowBoard` в main.js
только показывает статус).

**Почему именно отсчёт, а не другие варианты** (рассматривались):
- *Двухшаговое «Точно завершить?»* — второй точный клик на тач-экране сам по себе
  опасен, и нет времени передумать «в моменте».
- *Удержание (hold 1.5 с)* — неудобно пальцем, недоступно при моторных ограничениях.
- *Undo-тост после факта* — **невозможен для «Завершить смену»**: журнал append-only,
  `stCalc` не принимает повторный `shift_start` в тот же день.
- *Отсчёт* — ноль лишних кликов в нормальном случае (10 с незаметны), полное время на
  «я не то нажал», работает мышью и пальцем, не трогает модель данных.

**Страховочный контур**: P1.2 (правка события админом в отчёте) — отсчёт не спасает,
если телефон «нажал сам» в кармане без участия человека.

**Чек-лист тестов:**
1. «Завершить смену» → отсчёт → «Отмена» → в журнале пусто, статус не изменился.
2. «Завершить смену» → дождаться 0 → событие в журнале, уведомление в «ДисКо», кнопка is-used.
3. Открыть перерыв и закрыть его сразу → отсчёт виден (старый молчаливый игнор убрался).
4. В окне отсчёта закрыть вкладку → перезагрузить → действие НЕ применено.
5. Два устройства: отсчёт на телефоне, за 10 с смена закрыта на ПК → применение на
   телефоне — no-op, дублей `shift_stop` нет.
6. «Завершить отсутствие» — тоже отсчёт; «Временное отсутствие» (открытие) — сразу форма,
   без отсчёта.
7. «Отмена» в отсчёте, затем нормальное «Завершить смену» → работает.
8. Во время отсчёта другие кнопки нажаты быть не могут (disabled).
9. `node scripts/verify.js` зелёный.

   select count(*) from information_schema.columns

## Деплой пункта 3 (missclick-отсчёт + мгновенные уведомления) — пошагово

Почему уведомления приходили за 30–60 секунд: мгновенный вызов `notify` из браузера
блокировался CORS (в ответе на preflight не было заголовка `x-otp-key`), поэтому всё
доставлял только `cron` — раз в минуту. В коде `notify` это уже исправлено — осталось
передеплоить функцию.

### ШАГ 1. Передеплоить Edge Function `notify` (3 минуты)

1. Supabase → **Edge Functions** → `notify` → вкладка **Code**.
2. Замени содержимое на [supabase/functions/notify/index.ts](../supabase/functions/notify/index.ts) → **Deploy**.
3. Проверка preflight (может быть выполнена из браузера/консоли или любым HTTP-клиентом):
   OPTIONS на `.../functions/v1/notify` с заголовком `Access-Control-Request-Headers: x-otp-key`
   → в ответе `access-control-allow-headers` должен содержать `x-otp-key`.

### ШАГ 2. Передеплоить `cron` (если ещё не сделано после правки месяца)

1. **Edge Functions** → `cron` → **Code** → вставить
   [supabase/functions/cron/index.ts](../supabase/functions/cron/index.ts) → **Deploy**.
2. Расписание `* * * * *` и секреты остаются как были.
