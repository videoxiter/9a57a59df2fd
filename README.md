Тёмный интерактивный дашборд эффективности отдела технической поддержки + 10 персональных страниц роста. Статический сайт (HTML/CSS/JS), без бэкенда.

**Дашборд (только для руководителя, неугадываемый URL):**
`https://videoxiter.github.io/9a57a59df2fd/1bceb335668c/`

> Корень `https://videoxiter.github.io/9a57a59df2fd/` — пустая заглушка «404». Репозиторий переименован в случайный токен, чтобы базу URL нельзя было угадать.

## Что внутри

- **`1bceb335668c/index.html`** — главный дашборд (только для руководителя): рейтинг по среднему KPI, карточки сотрудников, динамика команды, радар с выбором сотрудника. Разделы дашборда: `/1bceb335668c/` (Моя команда), `/dynamics/`, `/people/`, `/duties/`, `/development/`, `/settings/`.
- **`team/<слаг>/index.html`** × 10 — персональная страница «Мои результаты» с **неугadываемым URL** (случайный токен) и **изолированными данными** (каждая страница содержит только своего сотрудника, без общего `data.js`).
- **Уволенные страниц не имеют.** Сейчас это Яковленков и Сафронов (`status: "left"` в `data.js`) — `generate_pages.py` их пропускает, папок `team/<их слаг>/` в репозитории нет и в публикации они отдают 404.
- **`index.html`** (корень) — заглушка «404».
- Геймификация: 10 уровней (Новичок → Посвящённый → Боец → Сержант → Офицер → Мастер → Гуру → Эксперт → Король → Легенда отдела), у каждого уровня свои бонусы; 17 наград. **Звёзды с сентября 2026 начисляет и снимает руководитель ОТП** (в журнале всегда указано, за что именно): рост и удержание KPI, новые награды, каждые 10 однотипных наград, вклад, который остаётся в отделе; снятие — падение KPI, замечания, нарушения. 10 ⭐ = +1 LVL, ниже границы уровня LVL падает.
- **Журнал звёзд с причинами** — на «Моём LVL» видно, за что начислена или снята КАЖДАЯ звезда: «Решение руководителя ОТП: +7 ⭐ — подготовка к роли "Главный специалист"», «Средний KPI упал: 9.20 → 7.00 (−2.20)…».
- **«Правила игры»** (книга из 13 глав на персональной странице): кто и как начисляет звёзды, шкала 10 уровней с перками, 17 наград с условиями и мотивацией, финансовые бонусы, дисциплина и безопасность.
- Рекомендации с фактами — каждый пункт плана ссылается на конкретный тикет (HELP-…).
- **Турнирная таблица команды** — на дашборде руководителя и на персональной странице **Павла Фролова**: подиум топ-3 (🥇🥈🥉 + звание по LVL), полный список по очкам (`LVL × 10 + ⭐`), глифы наград. Кому её отдавать, решает `BOARD_IDS` в `scripts/generate_pages.py`. У остальных специалистов доски нет ни на странице, ни в её исходнике — данные коллег им не отдаются.
- **Командные графики** для руководителя: вместо KPI-профиля по себе — средний профиль команды (радар) и динамика всех метрик команды (линия). Ссылок на чужие страницы нет нигде.

### Часы: что списывает, а что нет

Правило одно на весь сайт — функция `otp.reqDelta` в `assets/js/common.js`, её используют и дашборд, и личные страницы:

| Операция | Влияние на остаток |
|---|---|
| Увольнительная (`leave`) | **минус**, но не более 4 ч за раз; не списывается, если показатели позволяют (`no_deduct`) или заявка помечена «без списания» — кроме `forceDeduct` от руководителя |
| Переработка (`overtime`) | плюс |
| Корректировка (`adjust`) | плюс (положительная); отрицательная не списывает — списание бывает только увольнительной |
| Отгул за выходную смену (`dayoff`) | **не влияет** (ни плюс, ни минус) |
| Прочее | не влияет |

Остаток в журнале считается **по каждому сотруднику отдельно** — у главного специалиста в журнале лежат записи всего отдела.


### Формат текстового файла итогов

Один файл на сотрудника, имя = фамилия (`Завьялов.txt`). Внутри — блоки по месяцам:

```
ИТОГИ ЗА АВГУСТ 2026
👤 Максим Завьялов | Специалист технической поддержки (ночная смена)
📊 KPI за Август 2026: Хорошо
• Качество: 7/10 📈 (рост с 6)
• Обучаемость: 8/10 ➡️
• Инициатива: 7/10 ➡️
• Вовлечённость: 7/10 ➡️
• Требования к работе: 9/10 📈📈 (отличный рывок с 7)
💰 Бонусы за Август 2026: 2 500 руб.
▸ 2 500 руб. — Выполнение KPI месяца
✅ Что получилось круто:
• <факт с тикетом HELP-…>
❌ Зоны роста:
• <факт с тикетом HELP-…>
```

Поддерживаются оба стиля: эмодзи-заголовки и старый вариант (`!Достоинства и сильные стороны!` / `!Зоны роста!` / `Рекомендации для роста:`). Парсер берёт KPI, сумму бонуса, детализацию, сильные стороны, зоны роста, а также **«Твой план на <месяц>»** (шаги + «Твой результат») и **«💬 Напутствие»** — они свои для каждого месяца, привязаны к `YYYY-MM` и меняются при переключении месяца. Награды, LVL, звёзды, причины звёзд и рекомендации считаются автоматически.

## Ежемесячное обновление

### Входные данные, которых нет в git

Сборка читает четыре файла из `scripts/`, и все они закрыты `.gitignore` (`scripts/*.json`):

| Файл | Зачем |
|---|---|
| `extracted.json` | разобранные итоги по месяцам (основа `data.js`) |
| `schedule.json` | графики смен и отпуска из Confluence (`fetch_confluence.py`) |
| `roadmaps.json` | дорожные карты развития (`parse_roadmap.py`) |
| `cloud.json` | провайдер и публикуемый ключ Supabase для заявок на часы |

**Поэтому свежий клон сам по себе не собирается** — файлы нужно перенести с рабочей машины (или из папки-автора проекта) в `scripts/` перед первым запуском. Секретов в них нет: всё содержимое уже лежит в публичном `assets/js/data.js`.

> ⚠️ `extracted.json` нельзя терять: апрель 2026 пришёл из выгрузки Qwen и **в `itogi/*.txt` его нет** — из текстов он не восстановится. `parse_itogi.py` при отсутствии базы больше не падает, но создаёт файл с нуля и честно предупреждает, что месяцы вне txt будут потеряны.

### Вариант А (основной): текстовые итоги пофамильно

1. Положи файлы `itogi/<Фамилия>.txt` (новые месяцы можно дописывать в тот же файл).
2. Прогони пайплайн:
   ```bash
   cd <папка репозитория>
   PYTHONUTF8=1 python scripts/parse_itogi.py            # dry-run: показать, что распознано (ничего не пишет)
   PYTHONUTF8=1 python scripts/parse_itogi.py --write    # записать в extracted.json (бэкап .bak)
   PYTHONUTF8=1 python scripts/generate_data.py
   PYTHONUTF8=1 python scripts/generate_pages.py
   PYTHONUTF8=1 python scripts/generate_dashboard.py
   ```
   Каталог итогов можно переопределить переменной `ITOGI_DIR`.

### Вариант Б: экспорт Qwen-чата

1. Положи экспорт рядом с `scripts/extract_qwen.py` (или передай путь).
2. `PYTHONUTF8=1 python scripts/extract_qwen.py "<путь к export.json>"` → далее генерация как выше.

### Публикация

```bash
git add -A && git commit -m "данные: <месяц>"
git push
```

GitHub Pages подхватит пуш и пересоберёт сайт автоматически (~1 мин). Слаги не меняются — ссылки у сотрудников остаются прежними.

> ⚠️ После правок `assets/js/*` или `assets/css/*` поднимай `?v=N` в `scripts/generate_pages.py` и `scripts/generate_dashboard.py` (константа `V`) и перегенерируй страницы — GitHub Pages агрессивно кеширует.

### Проверка после публикации

```bash
npm i -D playwright-core          # один раз; нужен установленный Chrome
node scripts/verify.js            # обход опубликованного сайта
node scripts/verify.js "" --shots .verify/shots   # плюс скриншоты разделов дашборда
```

`scripts/verify.js` берёт список страниц из файловой системы (новые сотрудники попадают сами), проверяет код 200, ошибки консоли и `pageerror`, пустой `#root`, а также что после прокрутки не осталось прозрачных `[data-reveal]`. Код выхода 1, если есть проблемы.
